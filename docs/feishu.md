# 飞书个人助理

飞书是同一个 Host 个人助理的私聊入口，与桌面和手机共享聊天上下文、记忆、
项目范围和操作权限。每个 Host 配置一个飞书企业自建应用及一个本人 `open_id`。
首版只接受这个账号与机器人的私聊，群消息及其他账号的消息不交给助理。

## 接入

1. 在[飞书开放平台](https://open.feishu.cn/)创建企业自建应用，开启机器人能力，
   记录 App ID 和 App Secret。
2. 为应用申请私聊接收、机器人发送消息，以及图片和文件资源所需权限：
   `im:message.p2p_msg:readonly`、`im:message:send_as_bot`、`im:resource`。
   将自己加入应用的可用范围，按所在企业要求发布应用。
3. 在连接 MonoCode **之前**，打开官方 [API 调试台](https://open.feishu.cn/api-explorer)，
   选择刚创建的应用，再进入“通讯录” → “获取单个用户信息”。保持
   `user_id_type` 为 `open_id`，点击 `user_id` 参数旁的“获取”，在弹窗中
   选择本人并确认。调试台会把 ID 直接填入参数框，复制其中 `ou_` 开头的值。
   这一步无需调用 API、填写手机号或邮箱，也无需额外申请通讯录权限；无需
   机器人先收到消息或先建立长连接。
   若无法使用此选择器，可备用
   [通过手机号或邮箱获取用户 ID](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/contact-v3/user/batch_get_id)，
   按接口说明配置查询权限与数据权限范围，并指定 `user_id_type=open_id`。
   不同应用的 `open_id` 不可混用，不能填其他类型的 `user_id`、`union_id` 或 App ID。
4. 在 MonoCode 当前 Host 的助理设置中展开“飞书”，填写 App ID、App Secret
   和本人 `open_id`，保存并连接。连接前需要先启用助理。
5. 在飞书应用后台的“事件与回调”中选择“使用长连接接收事件”，订阅
   `im.message.receive_v1`。保存长连接配置时保持 MonoCode Host 运行并已连接。
   按后台提示发布包含事件订阅的应用版本；仅填写配置不代表已生效。
   具体流程参见[官方 SDK 长连接文档](https://github.com/larksuite/node-sdk/blob/main/README.zh.md#使用长链模式处理事件)。
6. 私聊机器人发送一条消息，确认助理聊天出现该输入、飞书收到回复。

桌面和手机使用同一份 Host 配置。关闭客户端不停止常驻 Host；Host 退出或断网
时不能接收新事件。已启用配置在 Host 启动后恢复连接，网络故障会重连并显示状态。
同一个飞书应用应只由目标 Host 使用，避免多个消费者竞争事件。

Secret 保存到现有权限保护下的 Host 数据库，不宣称加密存储；读取接口仅返回
是否已配置。保存相同 App ID 时留空表示保留原 Secret，更换 App ID 必须填写新值。
更换应用或本人账号会停止旧绑定尚未完成的交付，需要重新连接。

## 消息行为

- 飞书输入进入同一份助理聊天。桌面与飞书输入分别排队，同一飞书绑定的纯文本
  追问仍可使用 provider 已支持的运行中插话。
- 飞书接收其请求的公开回复，以及助理有效的事件跟进、习惯和提醒；桌面、手机
  普通对话不转发。首次启用不补发历史，助理的静默检查不会产生通知。
- 每个气泡完成后作为普通聊天消息发送，不逐条引用原消息；长文本按字节预算
  分段，工具日志和思考不进入飞书。请求与回答的对应关系保留在 Host 内部。
  任务卡转换为项目、会话和状态摘要，状态变化可以继续通知。
- 需要批准或结构化回答时，飞书显示提示，回到 MonoCode 处理。普通飞书文字
  不会被桥接层自动解释为批准决定。
- 支持文本、富文本中的文字和图片、独立图片及文件。每条输入最多 20 个附件，
  单个附件最多 20 MiB；不支持语音转写、视频处理和飞书交互卡片。
- 助理可通过 `reply.attachments` 明确选择项目文件或普通会话已有附件，发布为
  公开回复后传到飞书。复制文件及投递前均检查现有权限和项目范围；不会自动上传
  工具产物、Markdown 中的本机路径或私有 brain 内容。超过图片上传限制的图片
  保留原始字节，作为普通文件发送。

## 交付与恢复

入站先落 SQLite inbox 再确认平台事件，以稳定 command ID 提交给助理；重复事件
和 Host 重启不会重复接收同一请求。下载失败时保留顺序和重试状态。

出站按气泡分段和附件分别记录，固定发送 UUID，并保存平台消息 ID。成功的部分
不重发，明确的临时拒绝退避重试。响应丢失，或 Host 在发送过程中退出时，将该项
标为“送达状态未知”，不会自动当作未发送重发。设置中可以查看、重试或停止该项；
**人工重试未知项可能重复送达**。停止交付不会撤回已经发出的消息。

同一回复中未确认的分段会阻止其后续部分，独立提醒仍可交付。停用飞书会停止
接收和发送，已接受的助理工作遵循原生命周期；同一绑定重新启用后可继续待办。
渠道连接错误不会使 Host 或普通会话无法使用。

## 开发接口

`host/im/` 负责平台 SDK、规范化及渠道生命周期；`host/im-service/` 负责配置、
inbox/outbox 和助理桥接。固定直接依赖 `@larksuiteoapi/node-sdk@1.74.0`，保留
之前的适配器 loader。根目录 `npm ci` 的 postinstall 会安装 IM 独立锁文件依赖；
Host 构建会把飞书运行依赖打入 bundle，部署时无需另外安装 npm 包。

Host 宣告 `im.feishu.v1` 能力，RPC 使用已有设备认证与 Host 身份校验：

| 方法 | 用途 |
| --- | --- |
| `im.get` | 脱敏配置、连接状态、待办数量与失败/未知项 |
| `im.configure` | 保存 App ID、可选新 Secret、本人 open_id 与提示语言 |
| `im.control` | `enable`、`disable`、`reconnect`、指定项的 `retry` / `discard` |

旧远程 Host 显示更新提示；本机旧 Host 在空闲时按既有升级流程重新启动，有运行
中会话时保留服务并提示稍后重试。
