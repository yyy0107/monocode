# Feature Specification: Host 常驻个人助理

**Feature Branch**: `main`（沿用当前工作区；本次不创建或提交分支）

**Created**: 2026-10-05

**Status**: Implemented — Host 与客户端已接入；实际验收及未通过检查见 compatibility.md

**Input**: 用户希望 MonoCode 提供类似 IM 联系人的个人助理，持续运行在 Host，查看全部智能体、项目和会话，创建会话并以带助理标志的用户消息发送任务。已确定复用专用 agent 会话，支持用户消息、会话事件、定时检查三类唤醒；默认完整权限且可设置；助理聊天隐藏工具和思考，展示可点击跳转的会话卡片。

## User Scenarios & Testing

### User Story 1 - 和常驻助理聊天并安排任务 (Priority: P1)

用户从全局“助理”入口发送“看看所有项目，在前端项目用 Claude 新建会话处理登录问题”。助理读取实际状态，创建普通会话，发送任务，给出回复和会话卡片。

**Why this priority**: 串起最核心的查看、创建、派发和导航体验。

**Independent Test**: 开启助理并发送上述请求，在目标会话看到带助理标志的用户消息；点击卡片进入同一会话；关闭桌面后目标任务仍执行。

**Acceptance Scenarios**:

1. **Given** Host 有多个项目和智能体，**When** 用户要求查看全局状态，**Then** 助理基于实际数据回答，包含归档和编排 worker，标明不可用能力。
2. **Given** 用户提出明确任务，**When** 助理创建并发送任务，**Then** 目标出现在项目会话列表，消息标明助理身份，助理聊天出现对应卡片。
3. **Given** 目标正在运行，**When** 助理继续发消息，**Then** 遵循现有排队规则，卡片区分“已排队”和“已完成”。
4. **Given** 一轮包含工具调用和思考，**When** 用户查看助理聊天，**Then** 只显示回复、操作卡片和必要的输入／错误，隐藏工具日志与思考正文。
5. **Given** Host 已接受任务，**When** 关闭全部客户端后重连，**Then** 恢复聊天和卡片，不重新创建会话或发送同一任务。

### User Story 2 - 设置权限并处理会话输入 (Priority: P1)

用户允许助理像自己一样管理工作，也能逐项关闭能力或限制项目范围。设置立即约束后续动作。

**Why this priority**: 可配置完整权限是用户明确要求，必须与首个可用版本一起交付。

**Independent Test**: 分别验证配置、批准、回答、取消、队列、归档、删除、文件、Git 和编排控制；关闭对应权限后重试，确认没有相应副作用。

**Acceptance Scenarios**:

1. **Given** 首次开启且未改权限，**When** 请求 Host 和目标智能体支持的动作，**Then** 助理可以执行，遵循已有所有权和工作区规则。
2. **Given** 用户关闭发送权限，**When** 助理向任意目标发送或引导消息，**Then** 被拒绝且目标历史／队列不变，聊天显示简洁提示。
3. **Given** 目标等待批准或回答，**When** 对应权限开启且请求仍有效，**Then** 助理可响应；已经处理的请求不重复执行。
4. **Given** 用户缩小范围或暂停，**When** 先前排队动作准备执行，**Then** 按当前权限重新判断，不执行已撤销的动作。
5. **Given** 目标被外部 CLI 或编排控制，**When** 助理要求写入，**Then** 使用现有合法控制路径，不能控制时报告原因，不绕过所有权限制。

### User Story 3 - 会话变化时主动跟进 (Priority: P2)

助理观察完成、失败、等待批准和等待回答事件，按用户目标继续安排工作，必要时主动给出结果或待处理事项。

**Why this priority**: 提供跨会话的持续协调能力。

**Independent Test**: 关闭客户端，让目标分别完成、失败和等待输入；重连后看到相应跟进；重复事件不产生重复消息。

**Acceptance Scenarios**:

1. **Given** 事件唤醒开启，**When** 被观察会话有重要变化，**Then** 助理收到来源和当前状态，按权限与用户目标决定动作。
2. **Given** 多个事件到达且用户同时聊天，**When** 助理正在运行，**Then** 后续输入有序等待，用户消息优先，最多一轮并发。
3. **Given** 助理派发的任务完成又引发跟进，**When** 自动链持续增长，**Then** 保留因果关系并限制连续轮数，达到限制时暂停该链并说明原因。
4. **Given** 没有新结果或可执行事项，**When** 助理完成判断，**Then** 不发送无变化通知。

### User Story 4 - 定时检查、暂停和故障恢复 (Priority: P2)

用户设置“每小时检查未完成的任务，有进展再告诉我”。没有客户端连接时仍执行，用户能暂停、继续和查看故障。

**Why this priority**: 完成长期待命、定时触发与可预测恢复。

**Independent Test**: 用短测试周期且断开客户端验证检查；模拟重启和限流，没有重放已执行动作或集中补跑错过的检查。

**Acceptance Scenarios**:

1. **Given** 定时检查开启，**When** 到达执行时间且没有客户端连接，**Then** 开始检查并保存有效结果。
2. **Given** 停机错过多个周期，**When** 重启，**Then** 最多合并为一次新检查，保留下一次计划时间。
3. **Given** 助理执行中 Host 退出，**When** 重启，**Then** 该轮标记中断并等待明确继续；已接受目标动作不自动重发，空闲待命与未开始输入可恢复。
4. **Given** 模型暂时限流，**When** 调用失败，**Then** 显示退避状态，重试不重复目标动作；账户失效等待用户修复。
5. **Given** 用户暂停或关闭，**When** 新事件或定时时间到达，**Then** 不启动新轮；已派发普通目标会话按原生命周期运行。

### Edge Cases

- 删除、归档或断开的目标仍保留卡片，显示真实可用状态。
- 网络超时但命令已接受时，使用同一操作标识核对或重试。
- 旧 Host 明确显示功能不可用；旧消息缺少来源时沿用原显示。
- 助理自身状态和无关流式碎片不触发自我唤醒。
- 事件超过单轮上下文或容量时保留来源游标和合并记录，显示延迟，不静默丢失任务。
- 隐藏工具／思考不能隐藏必要的错误、权限请求和问题。
- 更换 provider 保留助理聊天，不能跨 provider 继续同一个原生执行会话。
- 历史卡片不能绕过当前权限或项目范围。

## Requirements

### Functional Requirements

- **FR-001**: 助理 MUST 由 Host 管理；关闭客户端不停止待命、检查和已接受工作；支持开启、暂停、继续和关闭。
- **FR-002**: 用户 MUST 能选择现有可用智能体和模型，复用已有登录与会话能力；切换后保留助理聊天。
- **FR-003**: 助理 MUST 查询所在 Host 已登记的全部智能体、模型、项目和会话，包括归档、已导入原生会话和编排 worker；标明实际可用能力。
- **FR-004**: 助理 MUST 在允许的项目创建普通会话并发送消息，遵循现有队列、原生所有权和编排控制。
- **FR-005**: 助理发送的用户消息 MUST 带持久可信来源标志，排队、同步、重连及历史读取后保留，客户端不能伪造该身份。气泡上方显示“来自 {设置中的助理昵称}”，昵称由 Host 提供；已有消息和排队消息跟随设置更新。
- **FR-006**: 助理聊天 MUST 提供类似 IM 的体验，显示回复和卡片，隐藏工具／思考正文，保留必要输入和错误。
- **FR-007**: 助理创建的会话 MUST 自动形成卡片，包含项目、智能体、标题和状态，点击进入确切目标。
- **FR-008**: 已开启助理 MUST 默认拥有所在 Host 支持的完整工作权限；用户可设置查看、打开项目、创建、发送、配置、批准、回答、取消、队列、归档、删除、编排、文件和 Git 等能力，并限制项目范围。
- **FR-009**: 权限 MUST 在实际动作前由 Host 检查，排队动作执行前再次检查；平台动作权限和智能体执行权限分别设置，说明各自覆盖范围。
- **FR-010**: 助理 MUST 支持用户消息、会话事件、定时检查三类唤醒，可独立开关，事件可按项目、会话和类型过滤。
- **FR-011**: 同一助理 MUST 最多一轮并发；后续输入有序等待、用户优先，重复事件合并，自动派发保留因果关系并限制循环。
- **FR-012**: 助理 MUST 持久保存配置、聊天、唤醒来源、操作结果和目标引用；重试不能重复创建、发送或处理同一输入请求。
- **FR-013**: Host 重启 MUST 不重放已开始但结果不确定的模型轮次或外部动作；空闲可恢复，中断需要用户明确继续。
- **FR-014**: 定时检查 MUST 保存下一次时间与提示，错过多周期至多合并为一次；无变化不重复通知。
- **FR-015**: 暂时限流 MUST 有可见退避状态；不支持能力、账户失效、权限撤销及存储失败明确报错，不声称未完成任务成功。
- **FR-016**: 桌面和移动端 MUST 连接同一 Host 助理、同步聊天、发消息和打开卡片；旧 Host 有明确回退。

  桌面助理 MUST 作为独立工作区页面打开，支持标签页切换、关闭和重启恢复，不仅提供悬浮窗口；重复打开复用同一页，切换保留草稿及聊天位置。
- **FR-017**: 新界面 MUST 支持英语和简体中文；用户提示与智能体输出保留原文；展开／收起均动画且尊重减少动态效果偏好。
- **FR-018**: 助理 MUST 保留普通聊天、原生导入及编排的生命周期和所有权；provider 未支持的能力保持不可用。
- **FR-019**: 用户发起的助理聊天 MUST 在生成过程中增量显示回复；同一回复保持稳定气泡及顺序，结束、取消或重启后保留已输出内容并结束流式状态。桌面与手机一致，工具／思考和静默标记不显示；自动巡检继续缓冲至确认有有效结果。

  回复展示 MUST 复用普通会话的逐字打字机逻辑，包含中文无空格文本、首批完整文本及在一次轮询前已结束的新回复；重新打开时已有历史立即显示，后续新增文本继续逐字显示。
- **FR-020**: 助理回复 MUST 支持桌面右键／手机长按菜单中的“回复”，将原文作为引用填入输入框，保留已有草稿且不自动发送；手机滚动不误触发，返回键优先关闭菜单。
- **FR-021**: 用户及助理消息 MUST 在气泡外下方显示发送时间和复制图标；复制保留消息原文并反馈成功／失败。用户消息 MUST 显示助理是否已读取：排队时未读，Host 开始处理该输入时已读，桌面与手机同步持久状态。

  首条消息前以及与上一条消息间隔达到 5 分钟的消息前，MUST 居中显示日期和时间；连续对话不按累计时长重复插入，流式／已读更新不改变分段。

### Key Entities

- **Assistant**: 一个 Host 的身份、名称、模型配置、权限、状态和全局聊天。
- **Brain session**: 当前 provider 的专用执行会话；切换 provider 时建立新会话。
- **Wakeup**: 用户、事件或定时输入及其来源、状态和因果关系。
- **Action**: 稳定操作标识、目标、权限判断、接受结果与完成状态。
- **Session reference**: 指向目标 Host、项目、会话的持久卡片引用。
- **Schedule / Watch**: 定时提示与周期，以及事件类型和项目／会话过滤条件。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 在两个项目、两个智能体的验收环境，通过一条请求完成查看、创建、发送和卡片跳转，不重新输入任务。
- **SC-002**: 断开全部客户端至少 10 分钟，完成事件和测试定时检查仍触发助理；重连恢复全部已接受消息和卡片。
- **SC-003**: 同一创建、发送、批准和回答请求提交 10 次，分别只产生一次效果；结果不确定时显示待核对状态。
- **SC-004**: 逐项撤销平台动作权限后，对应未执行动作全被阻止；客户端提交的来源不能显示为可信助理。
- **SC-005**: 没有积压或模型限流时，重要事件在 10 秒内纳入处理，卡片变化在客户端下一次同步显示。
- **SC-006**: 含 20 条工具／思考记录的验收会话不展示其正文，完整显示回复、卡片、必要输入和错误。
- **SC-007**: 重启、限流、撤权和旧 Host 场景有实际验证记录；未运行的智能体及平台组合明确列为未验证。

## Assumptions

- 首版每个 Host 一个助理，覆盖该 Host 的 MonoCode 状态；不同 Host 明确切换身份，跨 Host 聚合另定范围。
- “像 IM 软件”指 MonoCode 内的联系人与聊天，首版不接入外部 IM。
- 用户主动开启后平台权限默认全开，设置不增加逐次确认；所有权限制仍适用。
- 默认开启三类唤醒；事件关注完成、失败和待输入；定时默认每 60 分钟，可改周期和提示，无变化静默。
- 空闲时可释放模型进程；持续运行指 Host 持续接收与调度输入。
- 已登记会话包含已导入原生会话；未导入外部 CLI 历史不属于 MonoCode 已有会话。
- 首版持久上下文使用聊天、配置、订阅和操作结果；向量检索及独立长期记忆另行设计。

## Validation Scope

生命周期、权限、协议和恢复改变需要自动回归及真实客户端／智能体验收。设计阶段只验证文档一致性，不代表功能实现或真实模型兼容性通过。

## Mobile assistant layout refinement

手机端遵循用户提供的 Muse / Project Assistant 参考：居中助理标记、圆形导航按钮、大圆角回复气泡、轻量任务卡片和底部胶囊输入栏。使用手机主题与安全区域变量，适配窄屏及键盘；不增加尚未实现的语音或通话入口。设置复用已有 MobileSheet 底部面板，从底部向上展开、向下收起，隐藏右侧滚动条并保留滑动；暂停／继续／停用进入操作菜单。返回键依次关闭菜单、返回聊天、离开助理；草稿和历史滚动位置保留。桌面聊天与 Host 调度契约保持兼容。

## Assistant chat and settings refinement

桌面与手机共享改进：助理回复以 Markdown 呈现（用户消息保持原文），空会话显示欢迎提示，运行中显示处理指示，任务卡显示智能体图标和状态标签。桌面使用独立 chrome：头部含助理标记、Host 切换、状态点及暂停／停用／设置／关闭图标按钮；设置作为覆盖聊天区的独立页面（双向动画、Escape 返回）；输入框为一体化输入区，支持附件标签、自动增高、Enter 发送／Shift+Enter 换行和内联重试。设置表单按“基本信息／执行／权限／唤醒”分区，权限按领域分组并可整组切换，事件类型与项目改为标签选择，计划与事件字段随唤醒来源显示，次要字段收入“高级”；底部固定保存栏，未修改或校验失败时不可保存。Host 契约与 AssistantPatch 结构保持不变。

手机助理设置的单行输入框与多行文本框统一使用圆角底色和内边距，聚焦采用柔和的中性边缘，去掉蓝色外框及文本框拖拽角标。多行文本框随内容增高，到达上限后内部滚动；校验错误保留红色边缘，适配明暗主题与窄屏。
