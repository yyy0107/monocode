# Feature Specification: 会话专属标签与分屏切换

**Status**: Scoped implementation and focused regressions complete. Delivery build and Host checks passed; web checks have three unrelated Worktrees assertion failures. Native desktop acceptance is unverified.

## User request

文件、审查和页面标签应属于打开它们的会话。切换会话时，不应看到另一个会话的标签；返回会话时，应恢复它自己的标签和当前页面。界面提供按钮，在聊天与工具并排的分屏视图和聊天／工具共用标签栏的完整视图之间切换，参照用户提供的图 2 和图 3。

图片是交互和布局参考，不是额外指令。本功能记录独立于当前 `.specify/feature.json` 指向的 022 助理功能；不修改该指针或已完成功能的记录。

## Scope and ownership

通常一个 `WorkspaceTab` 承载一个会话，其 `editorPanes` 中的文件、计划、审查和应用页面归该会话工作区所有。相同路径或相同页面种类可以在不同会话中分别打开，不跨会话去重，也不跨会话替换临时预览。

用户主动创建的多会话分屏保留现有布局行为。此时 `WorkspaceTab` 是用户显式组成的会话工作区，工具面板仍由该工作区持有。首版不引入每个聊天叶子独立的工具布局映射，也不自动拆散已有多会话布局。会话从这种组合布局拖入另一工作区时，工具面板的归属需要单独验收；本功能不宣称已实现逐叶子迁移。

项目终端沿用现有项目级停靠区及生命周期。只读 worker 详情、已有文件独立工作区和旧版本独立应用页面应保持可用。

## Functional requirements

- **FR-001**: 从会话中的文件链接、计划和审查入口打开的内容进入该会话所属工作区。相同文件在两个会话打开时，两者的标签、临时预览和活动文档互不覆盖。
- **FR-002**: 设置、搜索、收件箱、笔记和自动化等应用页面在会话工作区内按种类去重；另一会话可以拥有同种页面的独立标签。
- **FR-003**: 普通会话选择、会话列表键盘导航以及本地／Host 会话切换恢复目标工作区的标签和已保存活动面板。切换会话不把原会话的工具标签移交给目标会话。
- **FR-004**: 文件和审查的异步路径解析在开始时确定来源及归属。解析完成后，会话切换不能重定向结果，失效或已替换的来源不能给新会话添加文档，也不能夺走用户当前焦点。
- **FR-005**: 提供会话工作区内的分屏／完整视图切换按钮。分屏时聊天和工具并排；完整视图时通过共用标签栏选择聊天或工具。按钮有明确的中英文名称及可访问名称。
- **FR-006**: 每个工作区保存 `surfaceMode`，并保留当前活动面板和每个面板的活动文档。重启、快照恢复和窗口转移保持这些选择；旧数据或非法模式回退到分屏。
- **FR-007**: 模式切换双向动画复用 `useCollapseMotion` 与 `animated-collapse-size`。关闭时保留零尺寸轨道，直接拖动调整尺寸时禁用过渡，快速反向切换可靠，遵循 `prefers-reduced-motion`。
- **FR-008**: 隐藏和关闭中的面板不可交互，其门户不应继续响应。聊天状态、编辑器内容和运行中终端在布局切换期间保留；隐藏不终止 PTY。必要内容至少保留到关闭动画完成。
- **FR-009**: 空白聊天已拥有工具面板时，打开其他会话不通过替换聊天叶子继承原面板。重置为新聊天清除旧的工具状态和显示模式。
- **FR-010**: 现有显式多会话布局、拖放、文件关闭／固定、预览、项目／工作树导航和持久化兼容。应用文本按 `docs/localization.md` 本地化；用户标题、路径和 provider 值保留原文。

## Acceptance scenarios

1. 会话 A 打开文件、审查及笔记；会话 B 打开另一文件及笔记。来回切换，标签和当前文档分别恢复；A 的笔记不把 B 带回 A。
2. A 打开一个延迟解析的文件或审查后立即选择 B。解析结果只更新仍有效的 A，B 保持当前焦点。解析期间关闭／重置 A 后，不在替代聊天中出现该内容。
3. 在一个会话中来回切换分屏／完整视图，选择聊天和不同工具标签。布局双向平滑变化，编辑内容、聊天草稿和终端进程保留；快速反转和 reduced motion 可用。
4. 重启后恢复两个会话各自的模式、活动面板和活动文件。旧快照、非法模式和同种独立页面均正确恢复。
5. 显式把两个聊天组成分屏后，仍能选择目标聊天、调整尺寸和使用现有拖放行为。工具归工作区持有的范围应清晰，不能据此声称逐聊天叶子所有权已经验证。

## Validation boundary

纯模型回归、React 测试和构建可证明状态与组件路径；不证明 Tauri 原生窗口、真实 PTY 或真实 Host 会话的端到端行为。实际执行结果及未验证场景记录在 `verification.md`。
