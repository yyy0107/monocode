# Implementation plan and contract

Reuse Session.queuedMessages/queueStatus and the shared MessageQueue card. Host persists queue state in the existing SQLite snapshot and delivers it through sessions.sync headers; no schema migration. HostSession optionally advertises supportsQueue/canSteer so old clients and old snapshots remain readable.

Existing send accepts a queued message when busy or a queue is pending. Entry IDs are command IDs. The Host starts FIFO heads with a stable hashed dispatch command ID, atomically removing the head and creating its user block using the original entry ID. Commands and receipts share one transaction; providers start after durable commit. Queue mutations use commands.dispatch with type=queue and action=hold/release/edit/remove/resume/steer. Edit/hold/release carry an opaque editor token; hold is renewed every 30 seconds and expires after 90 seconds. Steering carries the active run ID. Provider acknowledgement removes the row; rejection retains it paused, with a visible error. Ambiguous accepted steering is never replayed automatically.

Steering uses existing native interfaces for Codex, Claude, Cursor, OpenCode, Pi, OMP and Hermes. Grok, Fx and Antigravity retain FIFO operations with steering unavailable. No provider protocol changes. Pi 1.0.1 distinguishes prompt acceptance from agent_settled, and steer from follow_up; the existing adapter already implements this lifecycle. See local audited 1.0.1 docs and https://github.com/earendil-works/pi/blob/v1.0.1/packages/coding-agent/docs/rpc-commands.md. Keep one application queue for uniform editing, persistence and cross-provider synchronization rather than duplicating it in Pi's native follow_up queue. Desktop tabs with remote:// execution paths cannot dispatch a mirrored queue head; only the Host session with its absolute working path can dispatch it.

Verify Host lifecycle races, two independent clients over real HTTP, production Pi/OMP adapters over subprocess protocol fixtures, desktop remote UI and mobile controls. Real model executions for each CLI and real-device iOS interactions must remain explicitly unverified.
